# Dell T5600 — 2× CMP 50HX working baseline

Date: 2026-09-29

## Configuration

- Host: Dell Precision T5600
- GPUs: 2× NVIDIA CMP 50HX 10 GB
- NVIDIA driver: 610.43.03 patched CMP50 unlock
- PCIe Gen2 unlock: cmp50hx-gen2.service
- Persistence mode: Enabled
- Power limit: 145 W per GPU

Important observation:

Both cards initially did not enumerate reliably in the previous physical
slot arrangement. After swapping the two CMP 50HX cards between slots,
both cards initialized successfully together.

## PCIe layout

- GPU 0: 0000:02:00.0 — PCIe Gen2 x4
- GPU 1: 0000:04:00.0 — PCIe Gen2 x4

Both cards advertise PCIe x16 capability but currently negotiate x4.

## Direct PCIe bandwidth

CUDA 13.3 direct pinned-memory copy benchmark:

| GPU | PCIe link | H2D | D2H |
|---|---|---:|---:|
| CMP50 #0 | Gen2 x4 | 1.61 GB/s | 1.67 GB/s |
| CMP50 #1 | Gen2 x4 | 1.59 GB/s | 1.67 GB/s |

Transfer sizes 256 MiB, 512 MiB, and 1024 MiB produced effectively identical results.

Both cards report:

- LnkCap: Gen2 x16
- LnkSta: Gen2 x4

The near-identical bandwidth confirms that both CMP50 cards are operating consistently on the T5600 after swapping their physical slot positions.

GPU settings:
- 2x CMP 50HX 10 GB
- PCIe Gen2 x4 per GPU
- PL 145 W per GPU
- layer split 1:1 for dual-GPU tests

### pp512 / tg128

| GPUs | pp512 | tg128 |
|---:|---:|---:|
| 1x CMP50 | 1337.41 tok/s | 50.31 tok/s |
| 2x CMP50 | 1310.90 tok/s | 59.60 tok/s |

Observed change:
- prompt: about -2.0%
- generation: about +18.5%

### pp4096 / tg128

| GPUs | pp4096 | tg128 |
|---:|---:|---:|
| 1x CMP50 | 1270.57 tok/s | 49.79 tok/s |
| 2x CMP50 | 2060.86 tok/s | 59.49 tok/s |

Observed change:
- prompt: about +62.2%
- generation: about +19.5%

### Interpretation

For a model that already fits entirely on one CMP50, dual-GPU scaling depends strongly on workload shape.

At short prompt length (pp512), splitting the model across two GPUs does not improve prompt throughput and slightly reduces it.

At pp4096, dual-GPU prompt processing scales much better, reaching about 1.62x the single-GPU throughput.

Decode/generation improves by roughly 18-20% in both tests.

This indicates that the current dual Gen2 x4 PCIe configuration is fast enough to provide useful multi-GPU scaling for longer-context prompt processing, even though it does not provide near-2x decode scaling.

## 2026-09-30 — physical slot mapping and cooling observations

### Physical PCIe slot mapping

The two CMP50 cards both negotiate PCIe Gen2 x4, but they sit behind different CPU root ports:

```text
GPU0 = 0000:02:00.0 -> root port 0000:00:01.1
GPU1 = 0000:04:00.0 -> root port 0000:00:03.0
```

Root-port capabilities:

```text
00:01.1 -> LnkCap Width x4
00:03.0 -> LnkCap Width x16
```

Therefore:

- GPU0 / 02:00.0 is installed in the physical x4 path.
- GPU1 / 04:00.0 is installed in the physical x16-capable path.
- Both CMP50 endpoints currently negotiate only Gen2 x4.

This means an x4 -> x16 hardware-lane mod would only be useful on GPU1 while it remains in the current T5600 slot layout. GPU0 cannot exceed x4 on its current root port.

### Cooling behavior in dual-GPU layout

The card in the x4 slot (GPU0) runs noticeably hotter in the current dual-card layout.

Observed under heavy load before auxiliary airflow:

```text
GPU0: reached about 80 C, fan 100%, then workload/power dropped
GPU1: remained around low-60s C under load
```

The Dell chassis fans responded automatically as internal temperature increased:

```text
Other Fan: ~1570 RPM at Ambient 30 C
Other Fan: ~1940 RPM at Ambient 32 C
Other Fan: ~2310 RPM at Ambient 34 C
max reported: 3914 RPM
```

NVIDIA clock-event diagnostics showed:

```text
SW Power Cap            : Active
HW Thermal Slowdown     : Not Active
SW Thermal Slowdown     : Not Active
HW Power Brake Slowdown : Not Active
```

So the observed NVIDIA clock-event reason `0x4` was SW power capping, not a reported NVIDIA thermal-throttle event.

### Auxiliary airflow test

A high-flow 12 V / 4 A server fan was aimed at the GPUs as a temporary airflow test.

With GPU0 reduced to 130 W and GPU1 left near 184 W:

```text
GPU0: 55 C, fan 81%, 129.4 W
GPU1: 56 C, fan 72%, 176.2 W
Ambient: 32 C
```

After raising GPU0 to about 150 W:

```text
GPU0: about 58 C at about 151 W
GPU1: about 56 C at about 176 W
```

After raising GPU0 to about 170 W:

```text
GPU0: about 61 C at about 168 W
GPU1: about 57 C at about 177 W
```

The auxiliary fan nearly equalized GPU temperatures, strongly indicating that the large earlier temperature gap was dominated by local airflow/slot placement rather than an immediate GPU-core thermal-throttle condition.

Practical conclusion:

- GPU0 is the thermally disadvantaged card in the current dual-card layout.
- GPU1 currently cools better and does not need urgent service based on these measurements.
- GPU0 has not yet been serviced; testing it alone previously kept it below ~70 C.
- Until GPU0 is serviced or chassis airflow is improved, a lower PL on GPU0 is a practical temporary workaround.
