## Two simultaneous 3-GPU workers

Two independent llama.cpp servers were launched:

- GPU 0,1,2 → port 8081
- GPU 3,4,5 → port 8082

Parallel coding requests produced:

- Worker A: 3112 tokens, 32.217685 tok/s, 96.562 s
- Worker B: 2972 tokens, 31.861024 tok/s, 93.249 s
- Aggregate generation throughput: **64.07870967842297 tok/s**

This is the most important result of the project: on PCIe x1 without P2P, two independent 3-GPU workers deliver much higher aggregate throughput than one 6-GPU tensor-parallel worker.

## Single P104 PCIe x1 vs x4 — 2026-09-11

A practical one-GPU comparison was run to estimate the cost of the mining-board PCIe x1 link versus a P104-100 installed directly in a wider slot.

Test model and request:

- Model: `qwen3.5:9b`
- Runtime: Ollama
- Context: 4096
- Output: 512 tokens
- Temperature: 0
- Same 78-token asynchronous HTTP crawler prompt on both systems

| System | GPU | PCIe | Prompt tok/s | Generation tok/s | 512-token eval time |
|---|---:|---|---:|---:|---:|
| Huanan / Windows | 1× P104-100 8 GB | Gen1 x4 | **217.63** | **28.17** | **18.18 s** |
| AI6 / Ubuntu | 1× P104-100 8 GB | Gen1 x1 | **144.09** | **23.74** | **21.52 s** |

Observed difference:

- Huanan x4 prompt processing was about **51% faster** than AI6 x1.
- Huanan x4 generation was about **18.7% faster** than AI6 x1.
- AI6 x1 needed about **18.4% more generation time** for the same 512 output tokens.

AI6 was isolated to GPU 0 for this test. The other five P104 cards were idle at 0 MiB VRAM, while GPU 0 used about 4.8 GiB and reached 100% utilization. The AI6 test used the Pascal-compatible `cuda_v12` Ollama backend with Vulkan disabled and `CUDA_VISIBLE_DEVICES=0`.

This is a practical system-level comparison rather than a pure PCIe laboratory benchmark: the hosts use different operating systems, CPUs, memory subsystems, drivers, and Ollama/backend builds. Still, it shows that PCIe Gen1 x1 does **not** reduce single-P104 token generation by anything close to the 4:1 link-width ratio. For an LLM that mostly resides in VRAM, the observed generation penalty was on the order of 15–20%, while prompt processing was affected more strongly.

## Power and thermals

Typical llama.cpp tensor generation:

- 4-GPU active: ~67–73 W per active GPU, ~46–53 °C
- 6-GPU active: ~65–69 W per GPU, ~47–57 °C
- Idle with model loaded: ~10–11 W per GPU, ~41–46 °C

During the 6-GPU tensor run, total GPU power was roughly 396 W.

## Mining / stability validation

Before the AI tests, all six cards were stress-tested under RaveOS/lolMiner.

- Etchash: ~34.46–34.53 MH/s per GPU; total 206.99 MH/s; 786.6 W total GPU power
- Autolykos2: ~55.84–56.23 MH/s per GPU; total ~336.99 MH/s; 617.6 W
- ZelHash: ~142 sol/s total; 753.9 W
- BeamHash III: ~99.5 sol/s average; 734.3 W

No GPU errors were observed in the six-card Etchash validation run.

## Conclusion

For this motherboard, the best practical architecture is **3+3 independent workers** rather than one large tensor-parallel worker. The limiting factor is PCIe x1 communication and lack of P2P, not raw GPU compute.
