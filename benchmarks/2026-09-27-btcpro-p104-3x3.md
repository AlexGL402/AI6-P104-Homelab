# BTCpro P104 3+3 Benchmark — 2026-09-27

This document records a direct follow-up benchmark of the six-card P104 stack on the BTCpro host, using the same practical 3+3 architecture as the original BIOSTAR H81A system.

## BTCpro test platform

- 6× NVIDIA P104-100, 8 GB each
- ASRock H510 Pro BTC+
- Intel Celeron G5905, 2C/2T
- ~8 GB system RAM
- Ubuntu Server 24.04 LTS
- NVIDIA driver 580.173.02
- CUDA 12.8 used to build llama.cpp for Pascal compute capability 6.1
- llama.cpp built in a separate `build-p104` directory with conservative CPU flags for the G5905
- PCIe topology:
  - GPU 0: Gen1 x4
  - GPU 1-5: Gen1 x1
- CUDA P2P unavailable between the P104 cards

## Model and worker layout

Model:

`Qwen3-Coder-30B-A3B-Instruct Q4_K_M`

The GGUF is stored as four shards, approximately 18.5 GB total.

Worker layout:

- GPU 0,1,2 → port 8081 → `qwen3-coder-30b-gpu012`
- GPU 3,4,5 → port 8082 → `qwen3-coder-30b-gpu345`
- split mode: tensor
- tensor split: `1,1,1`
- context: 32768

The authoritative coding prompt was the same prompt preserved in the original H81 benchmark:

> Write a complete Python implementation of an asynchronous HTTP crawler with concurrency limits, retries, rate limiting, URL deduplication, structured logging, and unit tests. Explain the architecture and design choices in detail.

Both workers were queried in parallel.

## Repeated parallel runs

| Run | GPU 0-2 | GPU 3-5 | Aggregate |
|---:|---:|---:|---:|
| 1 | 32.937 tok/s | 32.107 tok/s | 65.044 tok/s |
| 2 | 32.973 tok/s | 32.017 tok/s | 64.990 tok/s |
| 3 | 32.966 tok/s | 31.990 tok/s | 64.957 tok/s |
| **Average** | **32.959 tok/s** | **32.038 tok/s** | **64.997 tok/s** |

The three aggregate results vary by less than 0.1 tok/s, so the measured throughput is highly repeatable.

## llama.cpp internal generation timings

For the same three repeated runs, the final llama.cpp `eval time` rates were:

- GPU 0-2: 33.52, 33.51, 33.54 tok/s → **33.52 tok/s average**
- GPU 3-5: 32.66, 32.72, 32.66 tok/s → **32.68 tok/s average**
- Internal aggregate: **66.20 tok/s**

The external HTTP benchmark is used for the main cross-system comparison because it includes the request wall time and is directly repeatable from the client side.

Repeated prompt-processing values after the first request are not comparable because llama.cpp reused the prompt cache; later runs evaluated only one new prompt token.

## H81A vs BTCpro

Original H81A result:

- BIOSTAR H81A Ver. 6.1
- Core i3-4130
- all six P104 cards at PCIe Gen1 x1
- two 3-GPU workers
- aggregate generation throughput: **64.0787 tok/s**

BTCpro repeated-run average:

- ASRock H510 Pro BTC+
- Celeron G5905
- first worker topology x4+x1+x1
- second worker topology x1+x1+x1
- aggregate external throughput: **65.106 tok/s**

Difference:

- **+1.027 tok/s**
- **+1.60%** for BTCpro in this practical 3+3 test

The first BTCpro worker averaged about 2.9% higher external throughput than the all-x1 second worker. This is consistent with the wider link on GPU 0 helping somewhat, but the generation workload remains dominated by GPU compute and inter-GPU synchronization rather than scaling directly with PCIe link width.

## GPU utilization during generation

During an active 3-GPU worker request, the participating cards were typically around:

- 93-95% SM utilization
- ~7.0 GiB VRAM used per GPU
- ~76-83 W per active GPU
- ~47-55 °C in the observed run

The other worker can remain loaded in VRAM while idle at 0% SM utilization.

## Result

The original project conclusion still holds: for six P104-100 cards without P2P, two independent 3-GPU workers are a strong practical layout.

The BTCpro host reproduces the historical H81 performance almost exactly and slightly exceeds it in the repeated parallel test:

- H81A: **64.08 tok/s**
- BTCpro: **65.11 tok/s average**
