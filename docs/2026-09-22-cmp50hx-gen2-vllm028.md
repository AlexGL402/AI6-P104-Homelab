Host: Ubuntu 24.04, kernel 6.8.0-139-generic

## CMP 50HX unlock / PCIe Gen2

Repository used:

- https://github.com/xrip/cmp50hx-unlock
- full patched build: stockflow + RT core count + ReBAR + PCIe Gen2
- ReBAR selector: 8 (16 GiB BAR1)

Build:

```bash
cd ~/cmp50hx-unlock
bash ./build.sh --card cmp50hx
```

Expected:

```text
PASS_CMP50HX_ALL_BUILD
```

Install:

```bash
cd ~/cmp50hx-unlock
sudo bash ./install.sh --card cmp50hx
```

Old local forge module path before replacement:

```text
/lib/modules/6.8.0-139-generic/updates/forge-cmp/nvidia.ko
```

The xrip installer moved the forge-cmp modules aside and installed the new modules at:

```text
/lib/modules/6.8.0-139-generic/updates/nvidia.ko
/lib/modules/6.8.0-139-generic/updates/nvidia-uvm.ko
/lib/modules/6.8.0-139-generic/updates/nvidia-modeset.ko
/lib/modules/6.8.0-139-generic/updates/nvidia-drm.ko
/lib/modules/6.8.0-139-generic/updates/nvidia-peermem.ko
```

### Old forge initramfs hook conflict

The old hook failed because the installer moved the forge-cmp module away:

```text
/etc/initramfs-tools/hooks/forge-cmp
```

It was renamed and made non-executable:

```bash
sudo mv /etc/initramfs-tools/hooks/forge-cmp \
        /etc/initramfs-tools/hooks/forge-cmp.disabled
sudo chmod -x /etc/initramfs-tools/hooks/forge-cmp.disabled
sudo update-initramfs -u -k $(uname -r)
```

### Gen2 service

Installed manually after the first installer run stopped at initramfs:

```bash
sudo install -m 0755 /opt/cmp50hx-unlock/cmp50hx/cmp50hx-gen2.sh \
  /usr/local/sbin/cmp50hx-gen2

sudo install -m 0644 /opt/cmp50hx-unlock/cmp50hx/cmp50hx-gen2.service \
  /etc/systemd/system/cmp50hx-gen2.service

sudo systemctl daemon-reload
sudo systemctl enable cmp50hx-gen2.service
```

After reboot, verified:

```bash
modinfo -n nvidia
nvidia-smi --query-gpu=index,pcie.link.gen.current,pcie.link.width.current,pcie.link.gen.max,pcie.link.width.max --format=csv
```

Working result:

```text
/lib/modules/6.8.0-139-generic/updates/nvidia.ko

index, pcie.link.gen.current, pcie.link.width.current, pcie.link.gen.max, pcie.link.width.max
0, 2, 4, 2, 16
1, 2, 1, 2, 16
```

So:

- GPU0: PCIe Gen2 x4
- GPU1: PCIe Gen2 x1
- both cards advertise max Gen2 x16
- before this change they were Gen1 x4 and Gen1 x1

Useful verification:

```bash
journalctl -u cmp50hx-gen2.service -b --no-pager
sudo dmesg | grep -E 'CMP50_GEN2|CMP50_STOCKFLOW|CMP50_REBAR' | tail -100
```

## 2026-09-24 — Huanan X99 single-card PCIe baseline

The AI6 Ubuntu disk and one CMP 50HX were moved to the Huanan X99 host for a clean PCIe-width baseline.

Observed topology:

- GPU: NVIDIA CMP 50HX 10 GB
- PCI address: `0000:04:00.0`
- CPU root port path: `00:03.0 -> 04:00.0`
- Current link: PCIe Gen1 x4
- Reported max width: x16
- Reported max generation in the current endpoint state: Gen1
- NVIDIA driver/KMD: 610.43.03

`nvidia-smi`:

```text
index, name, pci.bus_id, pcie.link.gen.current, pcie.link.width.current, pcie.link.gen.max, pcie.link.width.max
0, NVIDIA CMP 50HX, 00000000:04:00.0, 1, 4, 1, 16
```

Direct pinned-memory PCIe bandwidth using the same PyTorch methodology as the CMP40 validation:

| Transfer size | H2D | D2H |
|---:|---:|---:|
| 256 MiB | 0.79 GB/s | 0.84 GB/s |
| 512 MiB | 0.79 GB/s | 0.84 GB/s |
| 1024 MiB | 0.79 GB/s | 0.84 GB/s |

This is the pre-hardware-mod CMP50 baseline for future x4 -> x16 comparison on the X99 platform.

The card is currently back in the Gen1 endpoint-advertising state. Earlier, with the `xrip/cmp50hx-unlock` Gen2 patch/service active, the same CMP50 class successfully advertised and operated at Gen2. Therefore the present Gen1 result does not imply a Gen1-only hardware limitation; the Gen2 unlock path is simply not active in this host state.

## 2026-09-25 — Dell T5600 single CMP50 baseline

Host mapping used during this test:

- T5600 monitor: http://192.168.1.2/
- AI6 monitor: http://192.168.1.19/

Test card:

- GPU: NVIDIA CMP 50HX 10 GB
- PCI address: `00000000:03:00.0`
- NVIDIA driver/KMD: 610.43.03
- CUDA UMD: 13.3
- Power limit during initial check: 170 W
- PyTorch test environment: `torch 2.14.0+cu130`

PCIe capability/status:

```text
LnkCap: Port #0, Speed 5GT/s, Width x16
LnkSta: Speed 5GT/s, Width x4 (downgraded)
LnkCap2: Supported Link Speeds: 2.5-5GT/s
```

`nvidia-smi`:

```text
index, name, pci.bus_id, pcie.link.gen.current, pcie.link.gen.max, pcie.link.width.current, pcie.link.width.max
0, NVIDIA CMP 50HX, 00000000:03:00.0, 2, 2, 4, 16
```

Therefore the card is operating at **PCIe Gen2 x4**, while the endpoint reports a maximum width of x16.

Direct pinned-memory PCIe bandwidth:

| Transfer size | H2D | D2H |
|---:|---:|---:|
| 256 MiB | 1.51 GB/s | 1.56 GB/s |
| 512 MiB | 1.51 GB/s | 1.56 GB/s |
| 1024 MiB | 1.51 GB/s | 1.56 GB/s |

The result is stable across all tested transfer sizes and is approximately 2x the earlier Gen1 x4 Huanan X99 baseline (~0.79/0.84 GB/s).

Additional CUDA/PyTorch device-local checks on the same CMP50:

```text
D2D copy: 230.62 GB/s
FP16 GEMM: 49.17 TFLOPS
```

Repeat GEMM run:

```text
torch.float16: 48.66 TFLOPS
torch.float32: 8.57 TFLOPS
```

The repeated FP16 result is consistent (~48.7-49.2 TFLOPS), providing a useful compute baseline for this CMP50 on the T5600 before vLLM testing.
